# 熊窝 · 首页工作台 · 阶段零设计冻结

- 日期：2026-08-28
- 状态：阶段零完成，待进入阶段一
- 适用项目：`personal/`（`thebear617/bear-home`）
- 本阶段：只冻结设计与实现边界，不修改生产页面、路由数据或追踪数据

## 1. 设计目标

将当前分离的「路由表」与「生活仪表盘」组织成一个更像个人工作台的首页：

- 首页优先展示“今天”和常用入口，而不是把所有功能平铺成规则宫格；
- 使用中心节点与外围模块的环绕构图，形成明确的视觉焦点；
- 路由表以紧凑分组呈现，减少卡片高度和无效留白；
- 保留完整的路由表和追踪工作台，避免首页承担所有深度操作；
- 桌面端有空间构图，移动端仍然按自然阅读顺序稳定降级。

参考图只提供视觉方向：轻盈低对比度、半透明表面、圆角胶囊和中心围绕构图。图中的人物、文案、品牌图标和具体模块不属于必须复制的内容。

## 2. 页面层级决策

### 2.1 首页 `/`

首页改为组合型工作台，负责快速查看和快速进入：

- 顶部左侧：收起状态的圆形胶囊导航；
- 中央：今日核心节点；
- 外围：路由分组与生活信息模块；
- 页面下部或外围：习惯、工作、音乐等轻量摘要；
- 详情模块使用明确的进入按钮或链接跳转。

首页不直接承载完整的周视图、月视图、长期目标历史和完整追踪控制。

### 2.2 路由表 `/routes/`

保留独立路由页，但只保留分组视图：

- 删除列表视图；
- 删除瀑布流视图；
- 保留搜索、分类筛选、标签筛选和 `⌘K` / `Ctrl K`；
- 所有路由数据仍由 `src/data/site.js` 提供；
- 每个分类改成紧凑的链接簇或密集条目，不再使用当前的大型信息卡片。

### 2.3 生活仪表盘 `/dashboard/`

保留完整的生活仪表盘和追踪工作台：

- 天气、日历、歌单、GitHub 等生活模块继续可用；
- 今日习惯、工作计时、番茄钟、Side Project 继续可用；
- 周视图、月视图、长期目标和报告导出继续放在详情页；
- 页面可以沿用首页的视觉语言，但不强行把所有详细数据做成径向布局。

## 3. 首页空间构图

### 3.1 中心节点

中心节点是全页唯一的一级视觉焦点，暂定内容：

- 标题：`今天也慢慢过`；
- 当前日期；
- 一个今日进度环或简短进度数字；
- 当前工作的简要状态；
- 一个主要操作入口，例如进入完整仪表盘或开始工作计时。

中心节点不放大量列表，不同时展示周/月统计，不承担所有操作按钮。

### 3.2 外围模块位置

桌面端使用“钟面式”位置概念，而不是等宽等高的网格。位置是初始构图建议，实际实现允许根据视口微调：

| 位置 | 模块 | 内容密度 |
|------|------|----------|
| 左上约 10 点钟方向 | 个人站点 | 中等，展示紧凑链接簇 |
| 左下约 7–8 点钟方向 | AI 工具 / 常用链接 | 中等，展示常用入口 |
| 右上约 1–2 点钟方向 | 科研学习 / 校园服务 | 中等，突出科研入口 |
| 右下约 4–5 点钟方向 | 购物娱乐 | 低到中等 |
| 中上或中心旁 | 天气 | 低密度摘要，可打开预报 |
| 中左或中心旁 | 日历 | 低密度摘要，可翻月 |
| 中右或中心旁 | 我的歌单 | 低密度摘要，可进入播放器 |
| 中下方 | 习惯 / 工作摘要 | 低密度，提供详情入口 |

外围模块允许有轻微角度变化和不同尺寸，建议控制在约 `-4deg` 到 `4deg`，以制造自然错落感。不得依赖大量绝对定位来保证内容不重叠。

### 3.3 “旋转分布”的解释

本方案中的旋转是空间构图，不是持续动画：

- 模块在不同角度和距离上静态分布；
- 轨道线只作为低对比度的关系提示；
- 不自动旋转、不自动漂移、不改变卡片阅读位置；
- 如未来需要动效，另行设计并默认尊重减少动态效果设置。

## 4. 路由分组的密度规则

### 4.1 首页路由摘要

首页展示所有主要分类的入口，但不要求 28 条链接全部在首屏同时出现。首屏优先展示高频分类和高频链接，页面继续向下滚动时可看到其余分类。

单条路由在首页只显示：

- 本地图标或分类图标；
- 名称；
- 一行短描述或域名；
- 必要时显示标签。

完整描述仍然保留在数据中，并通过详情页、`title`、聚焦状态或其他可访问方式查看。

### 4.2 路由详情页

`/routes/` 使用同一份数据，但可以展示更完整的条目内容。分组内部优先采用紧凑双列或不等宽链接条目：

- 分组标题与数量保持明显；
- 不再默认只显示前 6 条；
- 不使用列表表格和瀑布流作为备用视图；
- 移动端允许分组折叠，但不能依赖悬停才能发现核心链接。

## 5. 追踪数据边界

首页只读取并展示追踪摘要，不重复挂载完整 `TrackingBoard`：

- `bear-home-tracker-v1` 仍是浏览器本地状态键；
- `/__tracker_sync` 和 `public/data/tracker-snapshot.json` 的同步协议不变；
- `src/data/tracker-config.js` 仍是长期目标配置源；
- 首页摘要只显示今日进度、工作时长、番茄钟或目标完成度等少量信息；
- 完整看板只在 `/dashboard/` 初始化一次。

实现时应优先抽出只读摘要计算，避免让首页和详情页分别复制一套 localStorage 解析和计时逻辑。

## 6. 组件分层建议

阶段一开始后，不把所有内容继续堆进一个 `index.astro`。建议形成以下职责边界：

| 层级 | 建议组件 | 职责 |
|------|----------|------|
| 页面编排 | `HomeCanvas.astro` | 组织首页模块和空间布局 |
| 导航 | `FloatingNav.astro` 或改造 `SiteSidebar.astro` | 左上角胶囊导航与当前页状态 |
| 中心节点 | `HomeFocusNode.astro` | 今日标题、日期、主进度与主入口 |
| 路由模块 | `RouteCluster.astro` | 首页和路由详情页共用紧凑分组条目 |
| 生活模块 | `DashboardSatellite.astro` 或拆分现有组件 | 天气、日历、音乐、GitHub 等摘要 |
| 追踪摘要 | `TrackerSummary.astro` | 只读今日摘要，不拥有完整计时状态 |
| 完整追踪 | `TrackingBoard.astro` | 继续负责 dashboard 详情页的全部追踪交互 |

这是一组职责建议，不要求阶段一一次性创建所有文件；可以先在现有组件中验证结构，再按复杂度拆分。

## 7. 视觉规范初稿

配色采用“雾紫 + 粉蓝 + 灰白 + 灰橙”的低对比度方向，与参考图的薄荷绿主色区分开：

| 用途 | 初始方向 | 备注 |
|------|----------|------|
| 页面背景 | 灰紫白、粉蓝雾化渐变 | 不使用强烈色块 |
| 普通表面 | 半透明暖白、鸽灰白 | 保持层次但不压暗背景 |
| 主文字 | 柔和蓝灰、深灰蓝 | 不使用纯黑 |
| 次级文字 | 中低明度灰蓝 | 确保仍可读 |
| 主强调 | 低饱和粉蓝或灰紫 | 用于中心节点和主要入口 |
| 辅助强调 | 灰橙、淡玫瑰 | 只用于状态或小图标 |
| 边框与轨道 | 半透明白、极浅蓝灰 | 关系提示应弱于内容 |

具体色值在阶段一落地时集中写入 CSS variables，不在各个组件中分别定义。

## 8. 响应式规则

### 桌面端

- 保持中心节点与外围模块的径向关系；
- 允许模块尺寸不同、轻微旋转和错位；
- 页面内容不依赖固定屏幕尺寸；
- 轨道线和装饰层不能抢过中心节点与链接内容。

### 平板端

- 减少外围模块数量和装饰线；
- 将低优先级模块合并为摘要条；
- 保留中心节点，路由分组改为两列或紧凑纵向排列。

### 移动端

- 不强行保持径向坐标；
- 采用固定阅读顺序：导航胶囊 → 中心节点 → 今日摘要 → 高频路由 → 其他模块；
- 不出现横向溢出、重叠或必须悬停才能操作的内容；
- 胶囊导航保持小而清晰，必要时只显示图标并提供可访问名称。

## 9. 分阶段实现计划

### 阶段零：设计冻结（本文件）

完成内容：

- 确定首页、路由详情页、仪表盘详情页的职责；
- 确定中心节点和外围模块的关系；
- 确定路由表只保留分组视图；
- 确定完整追踪数据不直接塞入首页；
- 确定不使用自动旋转动画；
- 确定桌面端径向、移动端线性降级原则；
- 确定配色方向和组件拆分边界。

### 阶段一：静态视觉骨架

只搭建首页画布，不重写业务逻辑：

- 新首页入口和胶囊导航；
- 中心节点；
- 外围模块占位与响应式结构；
- 背景、表面、文字、边框和轨道的设计 token；
- 以桌面和移动端截图检查构图是否成立。

### 阶段二：路由分组重构

- 移除列表/瀑布流的 HTML、JS 和 CSS；
- 将分组视图改成紧凑链接簇；
- 保留搜索、筛选和键盘快捷键；
- 将路由簇接入首页和 `/routes/`；
- 验证所有现有外链和本地文件条目仍可正确展示。

### 阶段三：仪表盘摘要与外围模块

- 将天气、日历、音乐、GitHub 等模块放入首页外围；
- 抽取追踪摘要；
- 保持天气预报弹窗、网易云移动端跳转和 tracker 同步行为不变；
- 完整 `TrackingBoard` 仍只在 `/dashboard/` 使用。

### 阶段四：首页组合与详情页收口

- `/` 正式成为组合首页；
- `/routes/` 成为完整紧凑路由页；
- `/dashboard/` 成为完整仪表盘页；
- 统一三个页面的导航状态、标题和返回路径。

### 阶段五：验证与清理

- 桌面、平板、移动端浏览器验收；
- 检查搜索、筛选、天气、音乐和追踪计时；
- 运行 `npm run build` 与 `git diff --check`；
- 清理无效的旧视图样式和重复覆盖规则；
- 检查 GitHub Pages 产物和固定端口行为。

## 10. 阶段零验收标准

阶段零视为完成，当以下设计结论都成立：

- 首页不是两个旧页面的简单上下拼接；
- 中心节点是明确的视觉和信息中心；
- 外围模块体现环绕和错落，而不是规则宫格；
- 路由表只有一种分组呈现方式；
- 首页摘要与完整仪表盘职责分离；
- 现有路由数据、tracker 数据和同步协议不需要迁移；
- 移动端有明确的线性降级方案；
- 阶段一可以从静态骨架开始，不需要重新讨论整体架构。

阶段零完成后，下一次实施只进入阶段一，不同时删除列表/瀑布流或重写追踪逻辑。
